# Протоколы хоккейных игровых дней

Превращает таблицу с данными по играм в печатные протоколы PDF — **по одному файлу на месяц**.

Исходник: `data/games.xlsx` (284 игры: июль — 194, август — 90).

## Что получается

| Файл | Что внутри |
|---|---|
| `reports/Протоколы_июль.pdf` | 194 игры, 31 игровой день, 56 листов А4 |
| `reports/Протоколы_август.pdf` | 90 игр, 15 игровых дней, 25 листов А4 |
| `reports/otchet_o_sverke.txt` | отчёт автосверки и список аномалий исходных данных |
| `reports/by_day/` | то же самое, но отдельным файлом на каждый игровой день (не в git) |

Один лист А4 — **4 карточки игр** (сетка 2×2) с полными составами по 7 игроков.
Судьи и секретари печатаются один раз внизу последнего листа дня, потому что
в пределах дня они не меняются.

## Главный принцип: данные не переписываются руками

Перенос делает программа, одинаково для первой и для 284-й игры. Значения
переносятся **ровно как в таблице** — ничего не пересчитывается и не «исправляется».

Каждая игра в Excel — жёсткий блок из 15 строк. Данные читаются **по позиции**
внутри блока, а подписи в левом столбце только сверяются: в исходнике есть
опечатки (`Навание соревнования`), и разбор не должен от них зависеть.

## Как поля таблицы попадают в протокол

| Поле протокола | Откуда берётся |
|---|---|
| СОРЕВНОВАНИЕ | «Название соревнования» |
| ДАТА / ВРЕМЯ | «Дата» / «Время начала матча» |
| КОМАНДА А / КОМАНДА В | «Команда 1» / «Команда2» |
| Таблицы составов (№ + ИГРОК) | «Состав команды 1» / «Состав команды 2», строка `ФИО №номер` |
| ИТОГОВЫЙ СЧЁТ | «Итоговый счёт матча» |
| СЧЁТ ПО ПЕРИОДАМ | «Счёт по периодам», первые три периода |
| ОВЕРТАЙМЫ | «Счёт по периодам», периоды после третьего |
| СУДЬИ / СЕКРЕТАРИ | «Судьи» / «Секретари» |

Два поля **вычисляются**, их нет в исходной таблице:

* **ПОБЕДИТЕЛЬ** — определяется по итоговому счёту; при равном счёте печатается «ничья»;
* **ОВЕРТАЙМЫ** — сюда попадает 4-й и далее период (в 29 играх период четвёртый).

Счёт печатается как `3 : 5` вместо `3*5` — числа те же, изменён только разделитель.

## Аномалии исходных данных

Найдены и **намеренно не исправлены** (перенесены как есть), список — в `reports/otchet_o_sverke.txt`:

* **8 игр**, где сумма голов по периодам не равна итоговому счёту;
* **3 опечатки** в подписях левого столбца (на разбор не влияют);
* **5 игр** вничью — в поле ПОБЕДИТЕЛЬ у них стоит «ничья».

## Запуск (C#, .NET 8)

```bash
cd HockeyReports
dotnet run --project HockeyReports -- ../data/games.xlsx ../reports
```

Пакеты ставятся сами: `ClosedXML` (чтение xlsx) и `QuestPDF` (генерация PDF,
бесплатная лицензия Community). Программа печатает отчёт о сверке и
возвращает код 1, если найдено расхождение переноса.

Шрифт: на Windows берётся `Segoe UI`, на Linux/macOS — `DejaVu Sans`.
Сменить можно через `PdfReportBuilder.FontName` или
`PdfReportBuilder.RegisterFont(путь_к_ttf, имя)`.

### Состав проекта

```
HockeyReports/HockeyReports/
  Program.cs             точка входа: прочитать -> разложить по месяцам -> сверить
  Models/Game.cs         одна игра ровно как в таблице
  ExcelReader.cs         разбор блоков по 15 строк
  PdfReportBuilder.cs    вёрстка листа А4: 4 карточки + судьи/секретари
  Validation.cs          сверка и список аномалий
  ScoreFormat.cs         разбор и печать счёта «3*5»
```

## Автосверка

Проверяется, что перенос точный:

1. число игр в Excel = число карточек в PDF (ничего не потеряно и не задвоено);
2. пополевая сверка каждой игры: все значения и все фамилии найдены в PDF;
3. контрольные суммы голов Excel = PDF.

Результат последнего прогона: **284 игры → 284 карточки, 0 расхождений,
суммы голов 1078 / 1067 сходятся.**

## Вспомогательные скрипты

`tools/build_reports.py` и `tools/validate.py` — та же логика на Python.
Ими собраны и проверены PDF, лежащие в `reports/`. Скрипт сверки дополнительно
**читает текст из готовых PDF** и сравнивает его с Excel — это и дало
пополевую проверку всех 284 игр.

```bash
python3 tools/build_reports.py   # собрать PDF
python3 tools/validate.py        # сверить PDF с Excel
```

> C#-проект в этой среде не компилировался (нет .NET SDK и его установка
> заблокирована сетевой политикой). PDF в `reports/` собраны и проверены
> Python-скриптами. При первом запуске C# возможны мелкие правки под версии
> пакетов.
